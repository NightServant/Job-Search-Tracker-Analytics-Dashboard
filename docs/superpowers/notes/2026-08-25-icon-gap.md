# Icon set gap — M4 Task 3

The 26-icon Figma set does **not** cover what the current screens use, so Lucide
cannot be removed in M4 Task 3 as the plan assumed. Recording the shortfall
rather than papering over it in either direction.

## Mapped — 9 of 21

`X→Close`, `Mail→Mail`, `Lock→Lock`, `Clock→Clock`, `Download→Download`,
`Upload→Upload`, `Moon→Moon`, `Sun→Sun`, `CheckCircle→Check`

## Missing — 12

`AlertCircle`, `Briefcase`, `ChevronDown`, `GripVertical`, `Loader2`, `LogOut`,
`RotateCcw`, `Save`, `Sparkles`, `Target`, `Trash2`, `User`

These are not decoration. `ChevronDown` is every disclosure control,
`GripVertical` is the kanban drag affordance, `Loader2` is every pending state,
`Trash2` and `Save` are destructive and primary actions respectively, and
`AlertCircle` carries error states.

## Drawn but unused — 13

`Overview`, `Applications`, `Calendar`, `Documents`, `Analytics`, `Settings`,
`Menu`, `ArrowRight`, `External`, `Database`, `Shield`, `Swatch`, `Text`,
`Layers`, `Play`

The set was drawn for the *redesigned* navigation and marketing surfaces, which
do not exist yet. That is why the overlap with today's screens is so thin — it
is a set built for M5 and M6, being measured against M0 code.

## Why Lucide stays for now

Uninstalling it breaks the build, and the twelve gaps sit almost entirely in
screens M5 rewrites: `JobsPage`, `ResumePage`, `DashboardPage`, `JobForm`,
`JobCard`, `ResumeVersionHistory`, `TemplatePresetSelector`. Replacing icons in
components that are about to be deleted is churn with a regression risk and no
lasting benefit.

**The roadmap constraint "`grep -r lucide src/` must come back empty" moves from
M4 4.3 to M5.** It is still a hard gate, just at the point where the screens
holding those imports are actually rewritten.

## How it was resolved — M5 Task 1

Options 1 and 2, as recommended. Nothing came from a second icon library.

**Eight drawn, taking the set from 26 to 34.** `AlertCircle`, `Briefcase`,
`ChevronDown`, `GripVertical`, `Trash`, `User`, `Target`, `RotateCcw` now live in
the Figma set `103:2066` alongside the original 26, at the same 20x20 frame and
1.75 stroke, and come through `scripts/generate-icons.mjs` like the rest. These
are the ones that carry meaning: a disclosure control, a drag affordance, an
error state and a destructive action are not decoration, and inventing a
second vocabulary for them would have split the set in half.

**Four eliminated, because a glyph that carries nothing should not be drawn.**

- `Loader2` became `<Spinner />` in `src/components/ui/spinner.tsx`. It existed
  only to be rotated, and a rotating drawing says nothing a rotating bordered
  circle does not. The pending state is the motion, not the picture.
- `Save`, `LogOut` and `Sparkles` become text buttons, in Tasks 4, 2 and 3
  respectively. Each sat beside a word that already said what it did, so the
  glyph was a second copy of the label in a form fewer people can read.

`Trash2` is drawn as `Trash`; the Lucide name carried a version number that
meant nothing here.

## What is still owed

The roadmap gate `grep -r lucide src/` still has to come back empty. Task 1 only
made that possible — the imports die with the screens that hold them, in Task 10.

## Closed — M5 Task 10

Nothing was still owed by the time Task 10 ran; Tasks 2-9 had already deleted
every import site the plan expected, except two the plan's own pre-flight scan
missed: `src/screens/LoginPage.tsx` (four imports — `Mail`, `Lock`, `Briefcase`,
`AlertCircle`) and `src/contexts/ToastContext.tsx` (one — `X`, not the three the
plan assumed). Both converted to the custom set; `lucide-react` uninstalled from
`package.json`.

Final tally against the eight drawn in Task 1: all eight now have call sites —
`AlertCircleIcon` (this screen's error banner, plus the panels documented
above), `BriefcaseIcon` (this screen's branding), `ChevronDown`, `GripVertical`,
`Trash`, `User`, `Target`, `RotateCcw` (M5's other screens). All four eliminated
as text controls stayed eliminated — no screen written since reintroduced a
`Save`, `LogOut`, `Sparkles` icon or a spinning `Loader2` glyph in place of
`<Spinner />`.

The gate is now a test (`src/__tests__/noLucide.test.ts`), not a grep run by
hand: one assertion on imports anywhere in `src`, one on `package.json`
dependencies. It checks import statements specifically, not the bare package
name, so this note and the docblock in `src/components/ui/theme-toggle.tsx`
can keep naming the dependency they steered around without failing their own
gate.

## Reversed — M5.5 Task 2b, 2026-08-29

**"Replace the custom icons with the new library."** Gabe's ruling. The
34-icon custom set this note documents building (26 original + 8 drawn in M5
Task 1) is deleted wholesale, not kept alongside AnimateIcons (MIT, installed
in M5.5 Task 2). This is a reversal of the decision this note records, made
for the same reason a hybrid was chosen the first time: one vocabulary, not
two. It was the right call when Lucide's coverage was thin against the
redesigned screens; a real, actively-maintained icon library covering all of
it removes the reason the custom set existed.

**What survives:** `src/components/icons/index.ts` keeps the barrel's export
shape from this file's era -- a `<Name>Icon` component per glyph, an `icons`
record, an `IconName` type -- so `nav-item.tsx`'s `icons[icon]` lookup and
`NAV`'s `IconName` typing needed no change. Three of the eight glyphs drawn in
M5 Task 1 had no AnimateIcons equivalent and were re-ruled: `GripVertical` ->
`ellipsis-vertical` (no grip/drag glyph exists in the set; three stacked dots
is the closest "drag me" affordance), `RotateCcw` -> `history` (the CV editor
sites mean "restore a previous version", which a history glyph says better
than a counter-clockwise arrow -- even though `refresh-cw` does exist in the
set, contradicting an earlier draft of the M5.5 plan). `Briefcase` has no
candidate at all -- searched `briefcase`, `bag`, `case`, `folder`, nothing --
and its one call site, `src/screens/LoginPage.tsx`, is a legacy v3 screen
M6 Task 4 deletes outright. Gabe's ruling: leave `LoginPage.tsx` untouched
rather than substitute a near-match glyph, so the exact geometry this note
describes drawing for `BriefcaseIcon` survives, isolated in its own file
(`src/components/icons/briefcase.tsx`), purely to keep that one screen
compiling until it is deleted. **The custom set is not quite 100%
wholesale-deleted** -- this one glyph is the exception, and it is temporary by
construction.

**What it costs:** every Figma frame in `si641ecd9VS70DJPLvtPfo` still draws
the deleted glyphs -- the set's component description at node `103:2066` reads
"Custom 20px icon set ... deliberately not Lucide or any imported library",
and that description is now false of the code. "Match the Figma" stops being
the acceptance test for icons from this point on; it remains the test for
everything else. The geometry differs too, not just the drawing: AnimateIcons
is a 24-unit viewBox at `strokeWidth="2"`, this set was 20 units at 1.75, so
icons read very slightly lighter than the frames they were drawn to match.
The Figma file should be updated to match the code, or the two will keep
disagreeing every time someone opens a frame -- a design task, raised with
Gabe rather than solved here.

`lucide-react` is still not reintroduced: AnimateIcons inlines its SVG path
data and depends only on `motion`. `noLucide.test.ts` stays and still passes.
