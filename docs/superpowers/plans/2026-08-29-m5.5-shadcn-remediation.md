## Global Constraints

Every task's requirements implicitly include this section. Values are copied verbatim from the roadmap and from M5's Global Constraints, plus the constraints this plan adds.

- **Never reintroduce `lucide-react`.** `src/__tests__/noLucide.test.ts` gates both the imports (`grep -rn "lucide-react" src`, filtered to real `from`/`require` lines) and the `package.json` dependency list. shadcn source ships with lucide imports; every installed component has them swapped for `@/components/icons` before it is committed. If a glyph does not exist in the 34-icon set, use the substitutions ruled in Task 2 — never invent an icon and never install the package "temporarily".
- **Accent is `#c2410c` (orange-700) light, `#fb923c` (orange-400) dark**, reached only through `--color-accent-default` / `--color-accent-hover`. orange-500 fails WCAG AA on white at 2.80:1 and is never used for text.
- **Status colours are semantic only:** wishlist grey, applied **blue**, interviewing **violet**, offer green, rejected red. Orange is never a status.
- **No status pills.** Status is a 2px rule plus a label (`StatusMarker`). This is why shadcn `badge` is not on the install list.
- **Radius caps at 4px.** `--radius` is set to `4px` in Task 2 and every shadcn component's `rounded-lg` / `rounded-xl` is rewritten to `rounded-md` at install time. Separation is hairline rules, not card borders or shadows — which is why shadcn `card` is not on the install list either.
- **Screens write no new component styling.** If a screen needs a visual the system does not provide, the component goes in `src/components/ui/` with a test, not inline in the page.
- **Font stack is `"Helvetica Neue", Helvetica, Arial, <fallback>, sans-serif`.** Helvetica Neue is licensed and cannot be self-hosted; do not attempt to download it. Task 2 adds the self-hostable metric-compatible fallback.
- **One `prefers-reduced-motion` gate:** `usePrefersReducedMotion()` from `@/hooks/usePrefersReducedMotion`. Never a second `matchMedia` call.
- **No kanban below 768px.** Mobile is a list with status tabs. Task 5 adds tabs to desktop; it does not add the kanban to mobile.
- **TDD is mandatory.** No production code without a failing test first, and the failure must be observed, not assumed.
- **The suite must be green at every commit, and the test count must never go down.** See the baseline note below — the count rule is why.
- **Supabase project is `somyuulytwgzltiboewm`.** Never `zlqepevzcfnnygaorvxn`. No task in this plan touches the database.
- **UI chrome is authored lowercase, in source, never with `text-transform`.** Nav labels, buttons, headings, panel titles, table column headers, form labels, empty-state copy and toasts are written lowercase in the JSX. Acronyms and codes keep their case: `CV`, `ATS`, `CSV`, `PDF`, `LaTeX`, and the ISO currency codes `PHP USD EUR GBP SGD AUD`. **User data is never transformed** — company, role, location, source, tags, tech stack, notes, CV content, email addresses and snapshot titles render exactly as stored. Full rule set and its exceptions in Task 12.
- **Every `data-*` test hook that exists today keeps its name.** `[data-body-header]`, `[data-kpi-strip]`, `[data-sidebar-logo]`, `[data-nav-item]`, `[data-theme-toggle]`, `[data-document-row]`, `[data-settings-group]` are all asserted on somewhere. Renaming one is a silent test deletion.

## Decisions locked before execution

Not open for re-litigation during execution.

**The sidebar collapse control is an addition, not a restoration.** The Figma sidebar (`19:11`, instanced at `20:28`) contains exactly: Logo, `Nav / Primary` (five numbered items), a 1px divider, `06 settings`, a flex spacer, Theme Toggle, and a three-line footer. **There is no collapse control anywhere in it, at either breakpoint.** Gabe asked for one; it comes from shadcn's `SidebarTrigger`/`SidebarRail`, and it is a deliberate departure from the frame. Say so in the commit message rather than implying Figma asked for it.

**The Figma has no dialog frames at all.** Searching every screen frame for `dialog|modal|overlay|drawer|sheet` in the layer names returns nothing. What the Figma *does* have is the Motion Specification row `smooth caret` (`43:571`), whose "where" cell reads **"auth, add job dialog"** and whose rule cell reads "Measure dialog-open cost across 14+ fields". That is the design's only statement about dialogs, and it confirms one was intended for adding a job. Task 4 therefore derives the dialog's chrome from the design system (hairline rules, 4px radius, no shadow, `bg-canvas`), not from a frame, and shadcn's `rounded-lg shadow-lg` defaults are overridden rather than accepted.

**`accent` means two incompatible things and the collision is resolved in favour of the design system.** In shadcn, `bg-accent` is the subtle hover surface. In this design system, "accent" is the orange brand colour. Today `--color-accent` is defined in the legacy block as `hsl(var(--accent))` = `210 40% 96.1%`, a pale blue-grey, so an unmodified shadcn component using `bg-accent` renders blue-grey while a Worktrack component using `bg-accent-default` renders orange, from names one character apart. **Every installed shadcn component has `accent`/`accent-foreground` rewritten to `bg-inset`/`text-primary` at install time**, and Task 11 deletes `--color-accent` from the legacy block once the last consumer is gone. Nothing in this repo may use `bg-accent` to mean orange or grey.

**`--primary` maps to the design system's accent, and the indigo ramp dies.** shadcn's `bg-primary text-primary-foreground` is its filled-button pair, which is exactly what `Button variant="primary"` already paints with `bg-accent-default text-accent-on-accent`. Task 2 defines `--color-primary: var(--color-accent-default)` and `--color-primary-foreground: var(--color-accent-on-accent)` so an unedited shadcn component is right by default rather than transparent.

**`--radius: 4px`, and that is the whole story for every installed component.** shadcn's stylesheet convention derives `rounded-sm/md/lg/xl` from `--radius` via `calc(var(--radius) - 4px)` … `calc(var(--radius) + 4px)`. With `--radius: 4px` that yields `sm: 0px`, `md: 2px`, `lg: 4px`, `xl: 8px` — and `xl` at 8px breaks the cap. So the cap is enforced twice: `--radius: 4px` sets the ceiling for `lg`, **and** every `rounded-xl` / `rounded-2xl` / `rounded-full` in installed source is rewritten to `rounded-md` before commit. A grep gate in Task 2 keeps it that way.

**Skeletons replace the spinner at route level and in panels; the `Spinner` component survives for in-button pending states only.** The Figma motion spec (`43:523`) is explicit: skeleton loading is for "charts, tables", 1200ms ease-in-out, and **"Shows after 200ms, so fast loads never flash."** That 200ms delay is a required behaviour, not a nicety, and it is why `Skeleton` gets a wrapper with a delay gate rather than being used bare. A 14px spinner inside a "Saving" button is not a skeleton candidate and stays.

**Status tabs go to every width; the kanban stays desktop-only.** Gabe's reasoning is recorded verbatim: the board cannot present a sorted view of everything. So the tabs become the sort/filter control for both views — on desktop they filter which columns the board shows and which rows the list shows; below `md` the board is still absent and the list is still the whole answer.

**shadcn `card` and `badge` are never installed.** They are the two components whose entire purpose contradicts a stated constraint — `card` is a bordered, shadowed, `rounded-xl` container in a system whose separation is a hairline rule, and `badge` is a pill in a system that banned pills. If a task's implementer feels they need one, that is a signal the layout is wrong, not that the constraint is.

**The lowercase rule is authored, not transformed, and the caps style survives because Figma authors it the same way.** Three reasons a container-level `text-transform: lowercase` is forbidden. It would also lowercase the acronyms and any user data rendered inside the container, breaking two of Gabe's own rules at once. The DOM text would stop matching the rendered text, so a copy-paste and a screen reader would both report something different from what is on screen. And it hides the whole change from code review, which is how a copy decision becomes a mystery six months later.

The one `text-transform` already in this system — `text-label-caps`, which uppercases — **stays, and Figma is the evidence.** Every Label/Caps text node in the file is *authored lowercase and displayed uppercase by the style*: the Recent Applications column labels at node `26:80` read `company`, `position`, `status`, `applied on` in the source and render through `tracking-[0.66px] uppercase`; so do the Motion Table's headers at `43:493` (`effect`, `where`, `duration`, `easing`, `rule`). So the caps style is Figma's own mechanism for exactly this, and adopting it means the source strings are lowercase — consistent with the rule — while one specific role renders as small caps. No conflict to resolve.

**Nothing in this plan touches the database, the services, or the hooks.** Every screen already has the data it needs, or has a hook that exists and is unused (`useEvents` for Task 7). If a task appears to need a new query, stop and report it.

```tsx
'use client'

import * as React from 'react'
import { Skeleton } from '@/components/ui/skeleton'
import { cn } from '@/lib/utils'

/**
 * The 200ms gate the Figma motion spec requires (node 43:523: "Shows after
 * 200ms, so fast loads never flash"). Every cached react-query read on this
 * app resolves well inside that, so without the gate a navigation between two
 * warm screens paints a full fake page for one frame and then replaces it --
 * which reads as a bug, not as a loading state.
 */
export function DelayedSkeleton({
  delayMs = 200,
  children,
}: {
  delayMs?: number
  children: React.ReactNode
}) {
  const [shown, setShown] = React.useState(false)
  React.useEffect(() => {
    const id = window.setTimeout(() => setShown(true), delayMs)
    return () => window.clearTimeout(id)
  }, [delayMs])
  return shown ? <>{children}</> : null
}

function Bar({ className }: { className?: string }) {
  // data-skeleton is the count hook the tests read; Skeleton's own classes
  // carry the 1200ms ease-in-out pulse from --duration-skeleton.
  return <Skeleton data-skeleton className={cn('h-4 w-full', className)} />
}

export function PanelSkeleton({ rows = 3 }: { rows?: number }) {
  return (
    <div className="flex flex-col gap-3">
      {Array.from({ length: rows }, (_, i) => (
        <Bar key={i} className={i === rows - 1 ? 'w-2/3' : undefined} />
      ))}
    </div>
  )
}

export type RouteSkeletonVariant = 'dashboard' | 'list' | 'table' | 'detail' | 'analytics'

/**
 * Route-level replacement for RouteLoading's centred spinner.
 *
 * The shapes are deliberately different per route: a skeleton whose job is to
 * tell you what is about to arrive stops doing that job the moment it is the
 * same grey rectangle on every screen.
 */
export function RouteSkeleton({ variant }: { variant: RouteSkeletonVariant }) {
  return (
    <DelayedSkeleton>
      <div role="status" aria-busy="true" className="flex flex-col gap-8">
        <span className="sr-only">Loading</span>
        {variant === 'dashboard' && (
          <>
            <Bar className="h-8 w-64" />
            <div className="grid grid-cols-2 gap-6 md:grid-cols-5">
              {Array.from({ length: 5 }, (_, i) => (
                <Bar key={i} className="h-16" />
              ))}
            </div>
            <div className="grid grid-cols-1 gap-6 lg:grid-cols-[460fr_300fr_280fr]">
              <Bar className="h-80" />
              <Bar className="h-80" />
              <Bar className="h-80" />
            </div>
          </>
        )}
        {variant === 'list' && (
          <>
            <Bar className="h-8 w-48" />
            {Array.from({ length: 6 }, (_, i) => (
              <Bar key={i} className="h-12" />
            ))}
          </>
        )}
        {variant === 'table' && (
          <>
            <Bar className="h-8 w-48" />
            <Bar className="h-6" />
            {Array.from({ length: 8 }, (_, i) => (
              <Bar key={i} className="h-10" />
            ))}
          </>
        )}
        {variant === 'detail' && (
          <>
            <Bar className="h-5 w-40" />
            <Bar className="h-8 w-72" />
            <div className="grid grid-cols-1 gap-6 lg:grid-cols-2">
              <Bar className="h-48" />
              <Bar className="h-48" />
            </div>
          </>
        )}
        {variant === 'analytics' && (

            <Bar className="h-8 w-48" />
            {Array.from({ length: 4 }, (_, i) => (
              <Bar key={i} className="h-40" />
            ))}
          </>
        )}
      </div>
    </DelayedSkeleton>
  )
}
```

- Dismissal is a bare `window.setTimeout` with no exit animation. The Figma motion spec (`43:559`) is specific: **160ms in / 100ms out, standard easing, "Out is faster than in. Always."**

```ts
// src/__tests__/copyCase.test.ts
import { execSync } from 'node:child_process'
import { describe, it, expect } from 'vitest'

/**
 * Chrome copy is authored lowercase in source. A container-level
 * `text-transform` would be easier and is forbidden: it would also lowercase
 * the acronyms and any user data rendered inside it, the DOM text would stop
 * matching the rendered text (so copy-paste and screen readers diverge from
 * the visible label), and the change would be invisible in review.
 *
 * These greps are a net, not a proof. They catch the two mechanical mistakes
 * -- reaching for text-transform, and lowercasing an acronym. Everything else
 * is a judgement call that lives in the diff.
 */
describe('copy case', () => {
  it('never lowercases with CSS', () => {
    const hits = execSync(
      `grep -rn "lowercase" src --include="*.tsx" --include="*.css" || true`,
      { encoding: 'utf8' }
    ).trim()
    const offenders = hits
      ? hits.split('\n').filter((l) => !l.includes('__tests__') && !l.trimEnd().endsWith('*/') && !/^\S+:\d+:\s*(\*|\/\/)/.test(l))
      : []
    expect(offenders, 'chrome copy is authored lowercase, never transformed').toEqual([])
  })

  it('keeps the acronyms uppercase in visible copy', () => {
    // Positive companion for the rule above: a repo that lowercased everything
    // would pass the first test and fail this one.
    const lowered = execSync(
      `grep -rnE ">[^<]*\\b(csv|pdf|ats|latex)\\b" src/components src/app --include="*.tsx" || true`,
      { encoding: 'utf8' }
    ).trim()
    const offenders = lowered ? lowered.split('\n').filter((l) => !l.includes('__tests__')) : []
    expect(
      offenders,
      'CSV, PDF, ATS and LaTeX keep their case in visible copy'
    ).toEqual([])
  })
```
