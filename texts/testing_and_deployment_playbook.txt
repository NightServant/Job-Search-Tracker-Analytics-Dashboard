================================================================================
      TESTING + DEPLOYMENT PLAYBOOK (LOCAL TO PRODUCTION)
================================================================================

Purpose:
This is the practical checklist for running, testing, and deploying the Job
Search Tracker app from your local machine to a hosted production URL.

Project stack summary:
- Frontend: React + Vite + TypeScript
- Backend/Auth/DB: Supabase
- Hosting: Vercel or Netlify (recommended), GitHub Pages (possible)


================================================================================
0. ACCOUNTS YOU SHOULD HAVE
================================================================================

Required accounts:
1. GitHub account
   - Needed to store repo and connect CI/CD deploys.

2. Supabase account
   - Needed for Postgres DB + Auth.
   - You need one active Supabase project.

3. Hosting account (pick one):
   - Vercel account (recommended), OR
   - Netlify account.

Optional accounts/services:
- Domain registrar (Namecheap, Cloudflare, etc.) for custom domain.
- Monitoring/logging tools (Sentry, LogRocket) if you want production tracking.


================================================================================
1. REQUIRED PROJECT SECRETS / CONFIG
================================================================================

This app currently uses these client environment variables:
- VITE_SUPABASE_URL
- VITE_SUPABASE_ANON_KEY

Where to get them:
- Supabase Dashboard -> Project Settings -> API.

Security notes:
- VITE_* variables are exposed to the browser by design.
- The SUPABASE ANON key is safe to expose in frontend apps when RLS is correct.
- Never put your SUPABASE SERVICE_ROLE key in frontend env files.
- Keep Row Level Security enabled on table(s), especially jobs.


================================================================================
2. LOCAL SETUP (FIRST RUN)
================================================================================

From project root:

1. Install dependencies
   npm install

2. Configure env file
   - Copy .env.example to .env.local
   - Fill in real values for:
     VITE_SUPABASE_URL
     VITE_SUPABASE_ANON_KEY

3. Apply DB schema in Supabase
   - Open texts/database_schema.txt
   - Run it in Supabase SQL Editor
   - Also run texts/database_schema_v3_migration.txt

3b. (Optional) Deploy the URL auto-fill Edge Function
   - Needed only for the "Auto-fill from URL" feature
   - Requires the Supabase CLI:
     supabase login
     supabase link --project-ref <your-project-ref>
   supabase functions deploy job-url-autofill

4. Auth setup checks in Supabase
   - Authentication -> Providers -> Email enabled
   - For easier dev testing: disable "Confirm email" (optional)

5. Start app
   npm run dev

6. Open local URL
   http://localhost:5173


================================================================================
3. LOCAL TEST CHECKLIST (MANUAL QA)
================================================================================

Run through this every time before deployment:

1. Auth flow
   - Sign up works
   - Sign in works
   - Sign out works
   - Session persists after refresh

2. CRUD flow for jobs
   - Create job entry
   - Edit job entry
   - Delete job entry
   - Move status through pipeline

3. Dashboard and analytics
   - Metrics update when jobs change
   - Charts render with data
   - Empty-state UI works when no data exists

4. Filters and search
   - Status filter works
   - Search by company/role works

5. Theming + responsive
   - Dark mode toggle works
   - App is usable on mobile width and desktop width

6. Export and script handoff
   - CSV export works
   - (Optional) Python script run:
     cd scripts
     python data_analysis.py


================================================================================
4. PRE-DEPLOY QUALITY GATE
================================================================================

Run these commands before pushing:

1. Lint
   npm run lint

2. Production build
   npm run build

3. Preview production build locally
   npm run preview

If build fails:
- Fix TypeScript/lint errors first.
- Check env variables are defined.
- Confirm Supabase project is active and schema is applied.


================================================================================
5. DEPLOY PATH A (VERCEL - RECOMMENDED)
================================================================================

1. Push latest code to GitHub.

2. In Vercel:
   - Add New Project -> Import GitHub repo
   - Framework: Vite
   - Build command: npm run build
   - Output directory: dist

3. Add environment variables in Vercel project settings:
   - VITE_SUPABASE_URL
   - VITE_SUPABASE_ANON_KEY

4. Deploy and verify:
   - Open deployed URL
   - Test login and job CRUD
   - Refresh deep routes (/dashboard, /jobs)

5. If deep route refresh returns 404:
   - Add vercel.json rewrite to index.html (SPA fallback).


================================================================================
6. DEPLOY PATH B (NETLIFY)
================================================================================

1. Connect repo in Netlify.
2. Build command: npm run build
3. Publish directory: dist
4. Add env variables:
   - VITE_SUPABASE_URL
   - VITE_SUPABASE_ANON_KEY
5. Add SPA redirect rule so all routes hit index.html.


================================================================================
7. DEPLOY PATH C (GITHUB PAGES, OPTIONAL)
================================================================================

Use this only if you want free static hosting and can handle SPA config.

Requirements:
- Configure Vite base path for repo-name.
- Add gh-pages deploy script.
- Add route fallback handling (404 redirect pattern).

Note:
GitHub Pages is less convenient than Vercel/Netlify for SPA apps with auth.


================================================================================
8. POST-DEPLOY SMOKE TEST (PRODUCTION)
================================================================================

After every production deploy:

1. Open deployed URL in incognito.
2. Sign up test user (or sign in with test account).
3. Create -> update -> delete one job.
4. Verify dashboard/charts update.
5. Verify logout/login cycle.
6. Verify hard refresh on /jobs and /dashboard works.
7. Verify Resume Maker -> Export PDF creates downloadable PDF in library.
8. Check browser console for runtime errors.
9. (Optional) Verify Auto-fill from URL works.


================================================================================
9. BASIC STAGING/PRODUCTION STRATEGY
================================================================================

If you want cleaner environments, use two Supabase projects:
- Staging Supabase project
- Production Supabase project

And two deploy targets:
- Preview/staging deployment tied to non-main branch
- Production deployment tied to main branch

Set env vars per environment in host dashboard.
Do not reuse production keys in staging if you can avoid it.


================================================================================
10. QUICK TROUBLESHOOTING
================================================================================

Problem: "Missing Supabase environment variables" warning
- Ensure .env.local exists with VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY
- Restart dev server

Problem: Login works, but no jobs visible
- Verify RLS policies from texts/database_schema.txt were applied
- Verify authenticated user owns inserted rows (user_id = auth.uid())

Problem: 404 on refresh in production
- Configure SPA fallback rewrite/redirect on hosting platform

Problem: Works locally but not in production
- Compare env vars in local vs hosting dashboard
- Confirm variables are set on the correct environment (preview/prod)

Problem: "Auto-fill from URL" fails
- Ensure the Edge Function `job-url-autofill` is deployed
- Ensure you are signed in (Edge Functions verify JWT by default)
